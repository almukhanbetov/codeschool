## 2. Структура программы

```
Program:  "CodeSchool — Полный курс программирования"  (slug: codeschool-full-curriculum, age 6–18)
 └── Level: "Год 1 — Визуальная логика и алгоритмическое мышление"  (position 1, age 6–8 — рекомендательный диапазон)
      └── Course: "Год 1: Визуальная логика и алгоритмическое мышление"  (slug: codeschool-year1-logic, 72 lessons, published)
```

- **Level ≠ индивидуальный уровень ученика.** Как и во всех предыдущих ступенях программы, `levels` здесь — это учебная ступень учебного плана ("Год 1"), а не оценка знаний конкретного ребёнка. Диагностика/оценка индивидуальной подготовки в этот стейдж не входила и не добавлялась.
- **age_from=6, age_to=8** на уровне и курсе — заданы как рекомендательные метаданные (те же поля, что и у всех остальных курсов платформы); в коде записи на курс (`enrollments.Service.Enroll`) по-прежнему нет возрастной проверки — значит возраст не блокирует запись, как и требовалось.
- Оставшиеся 6 ступеней (годы 2–7) **не создавались** — ни программ, ни курсов, ни тем более пустых уроков для них не заведено. `levels.position` зарезервирована и продолжается с 2 для будущих ступеней той же программы.
- Slugs стабильны и по образцу остальной платформы: программа/курс — `kebab-case`, все 72 урока — `y1-m{модуль}-l{номер}-{смысловой-слаг}` (например `y1-m4-l28-mug-and-content`).

## 7. Формат хранения учебного содержания

Проверено фактическое состояние **после Stage 33** перед началом работы: `lessons.content` оставалась одной TEXT-колонкой, фронтенд рендерил её как `<pre className="learn-content-body">{lesson.content}</pre>` — подтверждено прямым grep по `LessonLearnView.tsx` в начале этого этапа.

**Решение**: минимальный, полностью обратно-совместимый рендерер, **без изменения схемы БД**:

- `lessons.content` остаётся обычной TEXT-колонкой — никакая новая обязательная (или вообще какая-либо новая) колонка не добавлена, миграция не потребовалась.
- Новый компонент `frontend/components/learn/LessonContent.tsx` — собственный небольшой парсер безопасного подмножества Markdown (заголовки `#`/`##`/`###`, списки `-`/`1.`, блоки кода ```` ``` ````, абзацы, инлайн **жирный**/*курсив*/`код`, ссылки и изображения `[..](https://...)`) — рендерит **настоящие React-элементы**, `dangerouslySetInnerHTML` нигде не используется.
- Изображения дополнительно ограничены allowlist-ом хостов (сейчас пустой — в проекте пока нет пайплайна загрузки изображений; при появлении разрешённого хоста поддержка включится без изменений в новых уроках).
- **19 старых уроков не сломаны**: их простой неразмеченный текст проходит через тот же парсер как обычные абзацы (каждая непустая строка → `<p>`) — визуально страница выглядит чище (не моноширинным блоком), но данные не изменились и не потеряны. Подтверждено живым запуском фронтенда (`npm run build` чистый) — но точечная браузерная проверка именно одного из старых 19 уроков в этом стейдже **не проводилась** отдельно (см. §14 «Оставшиеся ограничения»); проверялись только новые 72 урока Year 1.

## 8. Стратегия seed

`backend/seeds/year1_curriculum.sql`, сгенерирован из авторского контента (9 файлов `module{1-9}.mjs` в рабочем скретчпаде — не коммитятся, финальный SQL — единственный артефакт в репозитории, как и остальные файлы `backend/seeds/*.sql`).

- **Идемпотентность**: программа и курс — `ON CONFLICT (slug) DO UPDATE`; уровень — `INSERT ... WHERE NOT EXISTS`; всё дерево модуль→урок→задание→квиз — один `DO $$ ... $$` блок, выполняющийся **только если у курса ещё нет модулей** (тот же приём, что уже используется в `backend/seeds/demo_learning.sql`).
- **Никаких `DELETE`/`TRUNCATE`/`DROP`** — весь файл состоит из `INSERT`/`SELECT`/одного управляющего `DO` блока.
- **Отдельная программа и отдельные сущности** — новый `program_id`/`level_id`/`course_id`, не пересекается ни с одним из 8 существующих курсов на платформе (проверено: разные `slug`).
- **Задел на 6 будущих ступеней** — `levels.position` начинается с 1 и однозначно продолжается; структура генератора (`generate.mjs` + `module{N}.mjs`) переиспользуема для годов 2–7 без изменений в SQL-шаблоне.
- Seed **не применялся** к production (production не существует — см. Stage 30, VPS не разворачивался) и **не применялся** к обычному dev-стеку (`docker compose up`, проект `codeschool`) — только к отдельному изолированному E2E-стенду (см. §9).

## 15. Педагогические ограничения

- **Нет визуального блочного редактора (как Scratch) в проекте.** Уроки 21, 22, 24 (модуль 3), 34, 36, 40 (модуль 5), 56 (модуль 7) и весь модуль 8 изначально в задании предполагали экранные визуальные инструменты, которых на платформе фактически нет. Каждый такой урок содержит явное поле «## Ограничение этого урока» с честной бумажной/физической альтернативой (рамки-циклы на бумаге, флипбук-анимация, бумажная марионетка, бумажно-настольная итоговая игра) — понятия года при этом не искажены и не имитируют несуществующий инструмент.
- **«Игра» как итоговый проект года — бумажно-настольная, не экранная.** Это соответствует ограничению выше и честно область применения расширится, когда/если на платформе появится визуальный конструктор для будущих ступеней.
- **Оценка открытых заданий требует учителя** — как и предписано: автоматическая проверка свободного текста нигде не выдаётся за доказательство понимания; все 66 text/project заданий идут через существующую очередь ручной проверки учителя.
- **Возрастной диапазон 6–8 — рекомендательный**, не проверяется кодом; адаптация формулировок/примеров для более старших начинающих учеников (упомянутая в ТЗ §2) оставлена на усмотрение учителя при живом преподавании — платформа не содержит автоматической возрастной адаптации текста.

## 16. Оставшиеся проблемы

- Точечная браузерная проверка одного из **19 старых уроков** через новый `LessonContent` рендерер не проводилась в этом этапе (только `npm run build` подтверждает отсутствие ошибок компиляции для всех страниц) — рекомендуется как первый пункт следующего связанного этапа.
- `LessonContent.tsx` использует обычный `<img>` вместо `next/image` (см. предупреждение линтера) — сознательное решение при пустом allowlist изображений; при добавлении первого разрешённого хоста стоит пересмотреть.
- Художественно-стилистическая методическая оценка контента (не структурная) выполнена выборочно (9 уроков из 72, по одному на модуль) человеком, а не исчерпывающе по всем 72 — заявлено прямо в §12, не скрыто.
- Годы 2–7 программы **не начаты** — ни данных, ни кода для них не создано, как и требовалось явно этим этапом.
